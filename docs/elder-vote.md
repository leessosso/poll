# 장로 선출 QR 출석 인증 투표 운영 가이드

이 문서는 `church-vote`에 추가된 장로 선출용 QR 출석 인증 투표 흐름을 설명합니다.

## 목표

- 기존 2청년회용 `open` 투표는 그대로 유지합니다.
- 장로 선출 투표에는 `attendance` 모드를 사용합니다.
- 성도는 입장 시 QR 출석 확인을 한 번만 하고, 각 후보 투표마다 찬성/반대/기권만 선택합니다.
- 관리자는 누가 투표했는지 여부만 확인하고, 무엇을 선택했는지는 볼 수 없습니다.

## 핵심 개념

### 참여 방식

| 모드 | 설명 |
|------|------|
| `open` | 기존 방식. 투표 사이트에 접속한 사람이 바로 투표합니다. |
| `attendance` | QR 출석 세션이 있는 성도만 투표합니다. 장로 선출용입니다. |

### 익명성 구조

장로 선출 투표에서는 데이터를 두 갈래로 나눕니다.

| 데이터 | 내용 | 관리자 노출 |
|--------|------|-------------|
| `participation` | 성도별 참여 여부 (`pending`, `completed`) | 가능 |
| `ballots` | 익명 선택값 (`찬성`, `반대`, `기권`) | 운영상 비공개 |

`participation`에는 선택값을 저장하지 않습니다. 따라서 관리자는 미참여자와 참여 완료자는 볼 수 있지만, 누가 찬성/반대/기권했는지는 볼 수 없습니다.

## 운영 흐름

### 1. 성도 출석 확인

실제 QR 스캐너 연동 전에는 관리자 화면의 `출석 인증 테스트/관리` 패널에서 성도를 등록하고 `출석 세션 생성` 버튼으로 테스트할 수 있습니다.

출석 세션이 생성되면 아래 형태의 투표 접속 URL이 발급됩니다.

```text
https://leessosso.github.io/poll/#/v/{sessionId}
```

같은 성도가 브라우저를 닫거나 기기를 바꿔 다시 스캔해도 같은 `voterId`로 판단합니다. 새로 발급되는 것은 `sessionId`뿐이며, 이미 완료한 투표는 다시 할 수 없습니다.

### 2. 투표 생성

관리자 화면에서 새 투표를 만듭니다.

권장 설정:

- 투표 유형: `찬반 투표`
- 참여 방식: `QR 출석 인증 필요`
- 기권 선택지: 포함
- 행사 ID: 예: `elder-vote`
- 제한시간: 예: 3분

기존 2청년회용 투표를 만들 때는 참여 방식을 `누구나 참여 가능`으로 두면 됩니다.

### 3. 투표 시작

관리자가 투표를 시작하면:

- 투표 상태가 `active`로 바뀝니다.
- 시작 시각과 종료 예정 시각이 저장됩니다.
- 해당 행사 ID의 출석 세션이 있는 성도들이 `participation`에 `pending`으로 들어갑니다.
- 관리자 화면에 실시간 미참여자 목록이 표시됩니다.

### 4. 성도 투표

성도 화면에는 다음이 표시됩니다.

- 성도 이름과 출석 확인 상태
- 현재 진행 중인 투표 제목
- 남은 시간
- 찬성 / 반대 / 기권 버튼
- 최종 확인 모달

성도가 선택을 완료하면:

- `participation/{voterId}`가 `completed`로 바뀝니다.
- 익명 `ballots` 문서가 생성됩니다.
- `polls.results` 집계가 증가합니다.
- 관리자 화면의 미참여 목록에서 해당 이름이 사라집니다.

### 5. 투표 마감

투표는 두 방식으로 마감될 수 있습니다.

- 제한시간 도달
- 관리자가 `투표 마감` 버튼 클릭

`attendance` 모드에서는 마감 시 아직 `pending`인 성도를 자동으로 기권 처리합니다.

```text
미참여자 -> participation completed
미참여자 수만큼 results.기권 증가
익명 ballots에 choice=기권 기록
```

`open` 모드는 미참여자 기준이 없으므로 자동 기권 처리를 하지 않습니다.

## 관리자 미참여 목록

관리자 화면의 미참여 목록은 “누가 아직 투표하지 않았는지”를 실시간으로 보여주는 운영용 목록입니다.

관리자가 볼 수 있는 것:

- 미참여자 이름
- 참여 완료 인원
- 전체 참여율
- 남은 시간

관리자가 볼 수 없는 것:

- 누가 찬성했는지
- 누가 반대했는지
- 누가 기권했는지

## 실제 QR 스캐너 연동 예정 구조

현재는 테스트용 수동 출석 세션 생성이 가능하며, 실제 QR 스캐너 연동은 아래 구조로 붙일 예정입니다.

```text
QR 출석 스캐너
  -> checkInFromQr(qrValue, eventId, scannerId)
  -> attendanceRawEvents 저장
  -> attendanceSessions 생성
  -> attendanceOutbox 생성
  -> 외부 출석 서버로 동기화
```

권장 데이터:

| 컬렉션 | 역할 |
|--------|------|
| `attendanceRawEvents` | QR 스캔 원본 로그 |
| `attendanceSessions` | 투표 인증에 사용할 당일 세션 |
| `attendanceOutbox` | 외부 출석 서버 전달 대기 큐 |

외부 출석 서버 전송이 실패해도 `attendanceSessions`가 만들어졌다면 투표는 진행할 수 있습니다. 전송 실패분은 관리자 화면에서 재시도하는 흐름으로 확장할 수 있습니다.

## 운영 전 확인할 내용

- 기존 QR에 어떤 값이 들어 있는지: 회원번호, URL, 암호화 값 등
- 출석 스캐너가 외부 API 호출을 지원하는지
- 외부 출석 서버로 어떤 payload를 보내야 하는지
- 총회 당일 유권자 기준: 출석자만인지, 사전 등록자 전체인지
- 제한시간 기본값: 3분, 5분 등
- 동률/가결 기준 등 교회 규정

## 운영 전 보안 보강

현재 구현은 기능 검증을 위해 클라이언트에서 Firestore를 직접 사용하는 부분이 있습니다. 실제 선거 운영 전에는 아래를 보강하는 것이 좋습니다.

- `castVote`, `startPoll`, `finalizePoll`, `checkInFromQr`를 Cloud Functions로 이전
- Firestore rules에서 `ballots` 직접 read/write 차단
- `polls.results` 직접 수정 차단
- 관리자 인증을 `VITE_ADMIN_PASSWORD`에서 Firebase Auth + 관리자 권한으로 이전
- 배포 전 테스트 모드 보안 규칙 제거

## 테스트 시나리오

1. 관리자 화면 접속
2. `출석 인증 테스트/관리`에서 성도 추가
3. `출석 세션 생성` 클릭
4. 표시된 `/#/v/{sessionId}` URL로 투표자 화면 접속
5. 관리자 화면에서 `QR 출석 인증 필요` 투표 생성
6. 투표 시작
7. 투표자 화면에서 찬성/반대/기권 선택
8. 관리자 화면에서 미참여 목록에서 이름이 사라지는지 확인
9. 제한시간 또는 마감 버튼으로 미참여자가 기권 처리되는지 확인
