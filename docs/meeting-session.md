# 모임 단위 현장 입장

## 무엇이 바뀌었나

- 현장 입장은 **모임(meetingId)** 단위다. 관리자 화면의 **새 모임 시작(입장 초기화)** 을 누르면 새 모임 id 와 새 입장 코드가 생긴다.
  지난 모임의 입장·현황판 번호 문서는 지우지 않고, 모임 id 가 달라 무시된다.
- 입장 코드는 규칙이 확인한다. 코드 원문(`meeting/current`)은 관리자만 읽고,
  규칙은 `entryCodes/{sha256(meetingId:code)}` 문서가 있는지만 본다.
- 입장 문서 `checkins/{meetingId}_{authUid}` 는 관리자와 본인만 읽는다. 이름·번호·uid 연결은 여기에만 있다.
- 투표자는 `claimedNames/{meetingId}_{voterId}`(필드: `meetingId`, `reissue`)로 이름이 이미 선택됐는지만 본다.
- 현황판 `lamps/{meetingId}_{badge}` 에는 번호와 상태만 있다. 유권자 id 는 없다.
- 입장은 브라우저 localStorage 에 남는다. 지워져도 같은 익명 계정이면 자동으로 다시 연결된다.
- 관리자 **다시 연결(재발급)**: 지금 기기의 입장을 회수하고 `reissues/{meetingId}_{voterId}` 에 번호를 남긴다.
  새 기기에서 입장 코드와 이름을 고르면 같은 번호로 들어오고, 이번 투표 참여 기록(투표 전)은 그대로 쓴다.
  이미 투표한 사람은 화면에서 막고, 규칙도 참여 기록이 `completed` 면 다시 투표하지 못하게 한다.
- 진행 중 집계(`polls/{id}/tally/current`)는 관리자도 읽지 못한다. 마감 뒤 관리자가, 결과 공개 뒤 투표자가 읽는다.

## 배포 순서

이전 사이트와 새 규칙, 새 사이트와 이전 규칙은 서로 맞지 않는다. 진행 중인 투표가 없을 때 연달아 올린다.

1. `firebase deploy --only firestore:rules,database`
2. `npm run deploy` (사이트)
3. 관리자 화면에서 **새 모임 시작(입장 초기화)** 을 한 번 누른다. 그 전에는 투표자 화면에 "아직 입장이 열리지 않았습니다"가 보인다.

## 데이터 이전

스크립트는 필요 없다.

- 예전 `meeting/current`(roomCode 만 있음)는 3번에서 새 모양으로 덮어쓴다.
- 예전 `checkins/{voterId}`, `lamps/{badge}` 문서는 남아 있어도 쓰이지 않는다. 관리자가 지워도 된다.
- 이미 마감된 투표는 그대로 보인다. 결과 공개 여부도 그대로다.
