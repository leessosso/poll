# 모임 단위 현장 입장

## 무엇이 바뀌었나

- 현장 입장은 **모임(meetingId)** 단위다. 관리자 화면의 **새 모임 시작(입장 초기화)** 을 누르면 새 모임 id 와 새 6자리 입장 코드가 생긴다.
  지난 모임의 입장·현황판 번호 문서는 지우지 않고, 모임 id 가 달라 무시된다.
- **코드 전용 입장**: 투표자는 명단에서 이름을 고르지 않고 6자리 입장 코드만 입력한다. 투표 화면은 `voters` / `voterDirectory` 컬렉션을 전혀 읽지 않아 무료 요금제 읽기 한도를 크게 아낀다.
- 입장 코드는 규칙이 확인한다. 코드 원문(`meeting/current`)은 관리자만 읽고,
  규칙은 `entryCodes/{sha256(meetingId:code)}` 문서가 있는지만 본다.
- 입장 문서 `checkins/{meetingId}_{authUid}` 는 관리자와 본인만 읽는다. 익명 계정 `authUid` 와 부여된 번호(`badge`) 연결만 들어가며, 기기당 1번만 입장할 수 있다.
- 현황판 `lamps/{meetingId}_{badge}` 에는 번호와 상태만 있다. 유권자 id 는 없다.
- 입장은 브라우저 localStorage 에 남는다. 지워져도 같은 익명 계정이면 `checkins/{meetingId}_{authUid}` 단일 문서 읽기로 자동으로 복원된다.
- 투표가 진행 중이 아니면 투표자 화면 오른쪽 위에서 **퇴장**할 수 있다. 본인 입장만 회수되고 현황판 번호가 비워지며, 같은 기기는 입장 코드로 다시 들어올 수 있다.
  이미 던진 표(`voteGuards`)는 비밀투표라 거둘 수 없고, 다시 입장해도 같은 투표에 두 번 투표하지 못한다.
- 진행 중 집계(`polls/{id}/tally/current`)는 관리자도 읽지 못한다. 마감 뒤 관리자가, 결과 공개 뒤 투표자가 읽는다.
- 투표를 시작할 때 관리자가 **투표 인원**(`expectedCount`)을 넣는다. 그 수만큼 표가 들어오면 투표가 마감된다.
  현장 입장 투표의 기본값은 이번 모임 입장 수다. 입장이 없으면 접속 수(열린 창 수)를 넣지 않는다.


## 배포 순서

이전 사이트와 새 규칙, 새 사이트와 이전 규칙은 서로 맞지 않는다. 진행 중인 투표가 없을 때 연달아 올린다.

1. `firebase deploy --only firestore:rules,database`
2. `npm run deploy` (사이트)
3. 관리자 화면에서 **새 모임 시작(입장 초기화)** 을 한 번 누른다. 이전 모임의 브라우저 캐시가 비워지고 새 코드로 입장하게 된다.

## 데이터 이전

스크립트는 필요 없다.

- 기존 `voters`, `voterDirectory`, `claimedNames`, `reissues` 문서는 지우지 않아도 된다.
- 이미 마감된 투표는 그대로 보인다. 결과 공개 여부도 그대로다.
